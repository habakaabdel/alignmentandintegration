Four things happen, in this order.

Every build runs the same way. You see the plan before a line is written, and someone stays after it ships.

  1. Research and consultation

    It starts with a conversation about how the work actually runs. Where it stalls, and which spreadsheet is quietly holding it together.

  2. Development and planning

    Then the shape of the work on paper: what gets built, what stays, in what order. You see the plan before a line is written.

  3. Building

    Software shaped like that, built on top of what you already have. Nothing gets ripped out to make room.

  4. Keeping it working

    Software is not furniture. Operations change, funders change their reporting, staff turn over. Someone who knows how it was built has to be there.
